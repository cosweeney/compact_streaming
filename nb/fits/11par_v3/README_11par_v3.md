# 11par_v3: sigma_0^2 = A_sigma * sigma_{v,lin}^2

Put this folder at `nb/fits/11par_v3/` (or anywhere; the scripts only need `compact` importable and, for the calibration
script, the path to `cosmologies.csv`). Baseline files are never touched: every new artifact carries the `11par_v3` tag.

## The model change

* Row 0 of the cosmology emulator is now `A_sigma` instead of `sigma0`. The model uses
  `sigma_0 = sqrt(A_sigma) * sigma_{v,lin}(theta, z)` with
  `sigma_{v,lin}^2 = (f a H / h)^2 / (6 pi^2) * int dk P_cb(k, z)` [km/s] (`compact/linear.py`).
* CAMB is called exactly as `GetLPTInputs` calls it: `camb.set_params(H0=100h, ombh2, omch2, As, ns)` and nothing else
  (CAMB 2.0.5 defaults: N_eff = 3.044, one 0.06 eV neutrino, w = -1, no running). **Check `camb.__version__` on calvinball**
  (older versions default to N_eff = 3.046).
* CAMB's f replaces Omega_m(z)^0.55 everywhere: the LPT mean velocity uses your existing `exact_growth` option (the new config sets `exact_growth = True`,
  which `CompactStreamingModel` already reads from the config), and sigma_{v,lin} always uses CAMB's f. Cost: `get_fsigma8/get_sigma8`
  < 1 ms against ~4 s for `get_results`; the extra CDM+baryon P(k) call is 0.03 s. CAMB's f is 0.3-0.5% above Omega_m^0.55.
* Two variants: `Config` (slopes on) and `ConfigNoSlope` (every ridge slope of every row zero, intercepts kept; sigma_0 still
  varies with cosmology through sigma_{v,lin}). Both live in the generated `config_11par_v3.py`.
* Baseline behaviour is unchanged: the new behaviour is switched on by two config attributes (`sigma0_from_linear`, `exact_growth`)
  that the baseline `compact/config.py` does not have. Checked against an unpatched copy of your tree (baseline config, 2 redshifts x 3 mass schemes, with and without `exact_growth`):
  the 11 compact parameters, the mean-velocity input, f, H, D_A and conv are bit-for-bit identical; the LPT xi(r) and v_r agree to <= 2e-14
  relative (roundoff; in a full-patch run they differ at that level although every partial application of the patch is bit-identical to
  unpatched, and I could not identify the mechanism). Compare old and new outputs with `np.allclose(rtol=1e-10)`, not exact equality.
  The extended `_lpt` tuple keeps `conv` last; every use of it in the repo's scripts and notebooks reads index 0, 1 or -1.

## Order of work

1. In the `compact_streaming` repo: `git apply --check nb/fits/11par_v3/compact_source_11par_v3.patch` and then `git apply nb/fits/11par_v3/compact_source_11par_v3.patch`; make sure the
   workers import this `compact` (see the install note in your pipeline document).
2. Calibrate. The script needs the per-(sim, z, bin) fits of the grid (`cosmo_grid_fit_results.h5`: the fitted sigma_0 of every sim is what A_sigma = sigma_0^2 / sigma_{v,lin}^2
   and its ridge are built from; the coefficients in `config.py` cannot be converted exactly because sigma_{v,lin}(theta) is not linear in theta). Candidates:
   * the copy tracked in the repo, `nb/drafts/auto_update/cosmo_grid_fit_results_numod.h5` ("numod" = the variable-nu, 11-parameter fits; `build_paper_cache.py` uses it as such);
   * the original that `cosmo_grid_building_nu.py` writes to `./figures/` of whatever directory it was run from (search `/home/cosweeney` as well as `/spiffball/cosweeney`);
   * a fresh one: re-run stage B of `cosmo_grid_building_nu.py` (from the repo root; it reads `.../halos/cosmo_grid/{sim}/{zdir}/data/pairhist_auto_mbin{k}.h5`, so stage A need not be redone).
   `bash check_fit_results_11par_v3.sh` runs the check below on the four candidates found on calvinball (or on files you pass as arguments) and prints date, size and checksum for each.
   `--check-only` (fast, no CAMB, works before the patch is applied) compares the sigma_0 emulator rebuilt from a candidate with the one in `compact/config.py`, evaluated at the grid cosmologies:
   ```bash
   find /home/cosweeney /spiffball/cosweeney -name 'cosmo_grid_fit_results*.h5' -printf '%TY-%Tm-%Td %TH:%TM  %p\n' 2>/dev/null | sort -r | head
   python calibrate_A_sigma_11par_v3.py --fit-results <candidate.h5> --check-only
   python calibrate_A_sigma_11par_v3.py --fit-results <chosen.h5> --cosmo-csv /path/to/cosmologies.csv --n-jobs 8
   ```
   On the repo copy the check gives: low_M identical (<= 2e-8); high_M differs by 0.14-0.26% at z <= 0.5, 1.8% at z = 0.8, 8% at z = 1.1, and has no fit at z = 1.4, 1.7. Because A_sigma
   for high_M above z = 0.5 is extrapolated from low_M (+ the mean shift at z <= 0.5), only the low_M data and the z <= 0.5 high_M data enter, so that copy is good to ~0.1-0.3% in sigma_0 for this
   comparison. A file that reproduces `config.py` exactly would be cleaner; the check tells you if you have one.
   Then `python check_highM_extrapolation_11par_v3.py --module config_11par_v3 --cls Config`: rows 0 (A_sigma), 5, 7, 8 and 10 should be listed as following the scheme.
3. `python smoke_test_11par_v3.py` (needs the new `config_11par_v3.py` and the patched `compact`).
4. `python generate_multiz_11par_v3.py` in tmux (resumable; my estimate is ~50 h for avg_M, both variants, 6 redshifts).
5. `python train_11par_v3.py`, then `python validate_11par_v3.py`.
6. Fits: see the entries below.

Adding mass schemes later: add `'low_M'` and/or `'high_M'` to `MASS_BIN_SCHEMES` in the generator and the trainer, and add the tags to
`SCHEME_STYLE` in the validator. `config_11par_v3.py` already holds low_M and high_M emulators. A later pass recomputes the LPT inputs for the
thetas it covers (~15 h per pass over all redshifts). The Gaussian emulators additionally need the same one-line A_sigma -> sigma_0
conversion in the `_pdf` of `generate_multiz_gauss.py` (`params[0] = sqrt(max(params[0], 0)) * lpt[-2]`) and a config that provides rows 0-3.

## Things that will not work as-is

1. **The source changes cannot live in this folder.** They modify `compact/` (a patch is provided, built on your current `lpt.py` and `predictions.py`; if those files change
   again before you apply it, `git apply --check` will fail and the three hunks are small enough to redo by hand). The baseline config still reproduces the baseline model with the patched code.
2. **`fits_apfix.py` is not in the repo copy I had**, so the fit entries above are for you to paste.
3. **The repo's cached fit results (`nb/drafts/auto_update/cosmo_grid_fit_results_numod.h5`) do not reproduce `config.py` exactly**: low_M sigma_0 matches to 2e-8, high_M differs by 0.1-0.3% in sigma_0 at
   z <= 0.5 (more above) and has too few high-M fits at z >= 1.4 (2 and 0 sims). I do not know whether it is an older copy or built with different cuts. For the A_sigma row the difference is
   small (see step 2), but `repo_cache_test_outputs/` was built from it, so regenerate the config on the file you choose before generating training data.
4. **With the 4-parameter (LCDM-only) sigma_{v,lin}, A_sigma is not cosmology independent across the calibration grid.** On the cached fits, the scatter of A_sigma
   about its mean is about 7% (low-M, z = 0.2-0.5; 5.6% at z = 1.7), against about 1.3% when sigma_{v,lin} was computed from each sim's full cosmology (w0, wa, N_ur, ...). At z = 0.5
   (low-M) A_sigma correlates with N_ur (-0.75) and w0 (-0.43). The ridge on the four LCDM columns fits sigma_0 about as well as the old emulator (rms of sigma_0 about the emulator,
   low-M: 2.8% vs 2.75% at z = 0.2, 2.6% vs 2.4% at z = 0.5, 1.6% vs 1.7% at z = 1.7), but a constant A_sigma gives 3.8% (z = 0.2) to 2.8% (z = 1.7). So expect the slopes-zero emulators to differ
   noticeably from the slopes-on ones. A later w0wa extension needs sigma_{v,lin} to depend on w0, wa (and probably N_ur) in both the calibration and the model.
5. **Row 0 changes meaning in `Config._MEAN_PARAMS`** and in any script that reads row 0 of the emulator as a velocity (the paper-figure scripts, `build_paper_cache.py`); use the baseline config there.

## What was tested here, and what was not

Tested (sandbox, CAMB 2.0.5): `linear.py` (multi-redshift and single-redshift CAMB agree to 1e-10; c000 at z = 0.2 gives sigma_{v,lin} = 310.33 km/s, matching the
earlier analysis); the patch applies cleanly to `a68c700`; the A_sigma -> sigma_0 conversion in `_pdf` (with a stubbed halotools) reproduces
sqrt(A) * sigma_lin and leaves the baseline config unchanged; the calibration script end to end on the repo's cached fit results; the generated config (11 rows and 11 mean
parameters at every node, rows 1-10 identical to the baseline, `ConfigNoSlope` has zero slopes and the same intercepts); the generator's plumbing with a stub model (LPT computed once per theta for both
variants, tagged directories, resume, adding a scheme later).
**Not run** (needs halotools, the Cython extension, EmulateLSS/TensorFlow and your data): the real `predict()`, the smoke test, generation, training, validation and fits.
